## M0 · 骨架与协议包

### 产出

```
pnpm-workspace.yaml
tsconfig.base.json
packages/protocol/
  src/frames.ts      # req/res/evt 的 Zod schema
  src/ops.ts         # 每个 op 的入参/出参 schema
  src/events.ts      # 每个 evt.type 的 payload schema
  src/errors.ts      # 错误码常量 + 类型
  src/index.ts
  package.json       # name: @agentlink/protocol, ESM only
packages/server/
  src/index.ts       # Fastify 启动
  src/config.ts      # 从 env 读取，缺失即报错退出
  src/logger.ts
  src/routes/health.ts
  .env.example
packages/web/        # Vite + React，先放一个占位页
packages/agent-sdk/  # 先空壳，M9 填
scripts/acceptance/
  _client.mjs        # 极简 WS 客户端（只用 node: 内置模块 + ws）
  _assert.mjs        # expect / expectError 断言
  run.mjs            # 跑指定里程碑的验收
```

### 硬性要求

- `@agentlink/protocol` **不得依赖 Fastify、React、better-sqlite3**。它只依赖 `zod`。
- 服务端启动时若 `JWT_SECRET` 未设置，直接退出并打印清楚的原因，不许静默用默认值。
- 开启 TypeScript `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`。

### 验收

```bash
pnpm -r build            # 全部通过
pnpm -r typecheck        # 全部通过
pnpm --filter @agentlink/server dev &
curl -s localhost:3000/healthz   # {"ok":true}
node scripts/acceptance/run.mjs m0   # harness OK
```

## M1 · 认证与会话

### 产出

- `POST /api/auth/login` → `{access_token(15m), refresh_token(30d)}`，argon2id 校验
- `POST /api/auth/refresh`（refresh token 轮换，旧 token 立即失效）
- `POST /api/admin/agents`（管理员建 agent）→ `{id, token}`，**token 只此一次返回**
- `POST /api/admin/agents/:id/rotate-token`
- WS `auth` / `ready` / `error`，5 秒超时 `close(1008)`
- op：`conv.create` / `conv.list` / `conv.get` / `group.update` / `subscribe.set`（先存内存）
- 迁移：`users`、`conversations`、`memberships`

### 验收

```bash
node scripts/acceptance/run.mjs m1
```

脚本必须覆盖：

1. 正确口令登录成功，错误口令 → 401。
2. WS 发正确 token → 收到 `ready`，`self.kind` 正确。
3. WS 发错误 token → `AUTH_INVALID` 且连接被关闭（close code 1008）。
4. WS 连接后 5 秒不发 auth → 被关闭。
5. 用户 A 建群，用户 B 调 `conv.list` 能看到。
6. 非成员调 `conv.get` → `PERM_DENIED`。
7. **断言 access_token 不出现在服务端访问日志里**（扫日志文件内容）。

## M2 · 消息与 seq

### 产出

- op：`message.send` / `message.get` / `message.revoke` / `history.fetch`
- evt：`message.new`、`message.revoke`
- 迁移：`messages`、`events`
- `client_msg_id` 幂等（捕获 `SQLITE_CONSTRAINT_UNIQUE`）
- 消息与事件在同一事务内写入

### 验收

1. A 发消息，B 在同一连接上收到 `message.new`，`seq` 比上一条大。
2. 同一 `client_msg_id` 连发两次 → 两次返回同一个 `message_id` 和 `seq`；`messages` 表只有一行；`events` 表只有一行。
3. `history.fetch` 分页：造 120 条，`limit=50` 连翻三页，无重复无遗漏，`has_more` 最后为 `false`。
4. 非成员发消息 → `PERM_DENIED`。
5. 撤回 → `message.revoke` 事件到达，`history.fetch` 不再返回它。
6. 一条消息 8001 字符 → `VALIDATION_FAILED`，`details.issues` 非空。

## M3 · 断线补齐 ⭐ 验收 3

### 产出

- op：`resume`
- `events` 回放（按 `seq` 升序，按订阅过滤）
- 30 天保留的清理定时任务
- `gap` 判定

### 验收

1. 客户端记录 `last_seq=20` 后断开；期间另一个人发 5 条；重连 `resume` → 依次收到 seq 21..25，`replayed=5`，`gap=false`。
2. 把 `events` 里 seq ≤ 20 的行删掉，再用 `last_seq=20` 重连 → `gap=true`。
3. 订阅只包含 `conv_ids:[c1]` 时，c2 的事件**不补发**，但 `last_seq` 仍推进到 c2 事件之后（说明空洞是正常的）。
4. `seq` 必须严格单调：并发发 200 条消息，断言 `seq` 无重复、无回退。

## M4 · 流式 ⭐ 验收 1

### 产出

- op：`stream.begin` / `stream.delta` / `stream.commit` / `stream.abort` / `stream.interrupt`
- evt：`message.update`（`seq=null`）、`message.final`
- `rev` 单调递增
- 节流落库（500ms / 512 字符）
- 启动时僵尸清理、60 秒超时

### 验收

1. 完整时序：`begin` → 3 次 `delta` → `commit`，客户端依次收到 `message.new(streaming)`、`rev=1,2,3`、`message.final`。
2. **丢帧自愈**：客户端丢弃 `rev=2`，收到 `rev=3` 时检测跳变，自动 `message.get` 并重置。
3. **节流**：100ms 内发 10 个 delta，断言数据库 `messages` 的 UPDATE 次数 ≤ 2（用 SQLite `PRAGMA data_version` 或加一层写计数器断言）。
4. `interrupt` 后 agent 继续发 delta → 收到 `STREAM_CLOSED`。
5. `kill -9` 服务端，重启 → 残留的 `streaming` 消息被 `finalize`，内容不为空则保留。
6. 60 秒无 delta → 自动 abort。

## M5 · 群管理与审计 ⭐ 验收 2

### 产出

- op：`member.invite` / `member.kick` / `member.mute` / `member.role.set` / `poke.send`
- evt：`member.join` / `member.leave` / `member.update` / `group.update` / `typing` / `poke`
- `audit_logs` 写入
- 权限矩阵（协议 §10）
- 限流（协议 §11）

### 验收

1. admin 踢人 → 成功，且 `audit_logs` 新增一行 `action='member.kick'`。
2. member 踢人 → `PERM_DENIED`，且**没有**审计记录（失败动作不写审计）。
3. 禁言中的成员发消息 → `PERM_DENIED`，`details.reason='muted'`。
4. 60 秒内发 31 条 → 第 31 条 `RATE_LIMITED`，`details.retry_after_ms > 0`。
5. owner 把 admin 降级 → 该 admin 再踢人 → `PERM_DENIED`。

## M6 · Web 客户端 ⭐ 验收 5

### 产出

- 登录页、会话列表（左）、聊天窗（右）、成员面板
- 消息气泡：自己右侧主题色，他人左侧浅底；含头像、时间、昵称
- 输入框：文本、多行、Enter 发送 / Shift+Enter 换行、附件按钮
- 虚拟滚动（`@tanstack/react-virtual`），向上滚动加载历史
- 流式渲染：订阅 `message.update`，按 `rev` 拼接，跳变则 `message.get`
- 断线重连：指数退避 + `resume`
- 两套主题（CSS 变量切换）
- 管理面板路由：建群、成员操作、审计日志

### 验收

1. 两个浏览器窗互聊，对端 200ms 内出现（同机）。
2. 一个窗输入时另一个窗看到 `typing`。
3. 造 1000 条消息，滚动流畅（用 DevTools Performance 记录，长任务 < 50ms）。
4. agent 流式回复逐字增长，肉眼可见。
5. 拔网线 30 秒再插回 → 消息补齐，无需刷新页面。
6. 群管理面板：踢人后该成员立即从成员列表消失。

## M7 · 附件

### 产出

- `POST /api/attachments`（multipart，≤ 20 MiB，按 sha256 内容寻址落盘）
- `GET /api/attachments/:id/:filename`（需鉴权 + 群成员校验）
- 消息 `content` 支持 `image` / `file` 块

### 验收

1. 上传 5 MiB png → 得到 `attachment_id` → 发消息引用 → 另一客户端能渲染。
2. 上传 21 MiB → 413。
3. 非群成员请求附件 URL → 403。
4. 相同文件上传两次 → 磁盘只存一份（sha256 去重）。

## M11 · 插件钩子与多实例

### 产出

- 服务端钩子：`onMessageIn(msg) => msg | null`（返回 null 则丢弃）、`onMessageOut(msg) => msg`
- 钩子以本地 ESM 模块加载，路径由环境变量指定
- 多实例：N 个 agent 进程各持自己的 token 与配置，互不影响

### 验收

1. 钩子把消息里的 `foo` 改写成 `bar`，客户端收到的是 `bar`。
2. 钩子返回 null，消息不入库、不推送。
3. 同时跑两个 agent 实例，各自只收到自己订阅的事件。
