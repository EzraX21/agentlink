# 05 · 施工守则

给实现者（人或 AI）。**这份文件的约束力高于你的个人偏好。**

---

## 1. 你要建的是什么

三句话：

1. 一个自研的即时通讯服务端，WebSocket 承载实时消息，HTTP 承载登录、历史、上传。
2. 一个自研协议（`AgentLink v1`），AI Agent 是**一等公民**：能按过滤订阅事件、能一步取到可直接拼 prompt 的上下文、能流式回复并被打断。
3. 一个 React 单页客户端，视觉参照 Telegram Desktop。

**不是**：Telegram 客户端换后端、QQ 协议端、Matrix 部署、通用 bot 框架。

---

## 2. 权威顺序

文档冲突时按此优先级裁决：

| 冲突类型 | 谁赢 |
|----------|------|
| 意图/范围 | `01` 需求确认书（根目录 `需求确认书.md`） |
| 字段、帧、时序、错误码 | `02` 协议规范 |
| 表结构、索引、事务 | `03` 数据模型 |
| 实现顺序 | `04` 实现计划（只是顺序，不是规格） |

协议规范没写到的地方，选**最简单**的实现，并记进 `docs/DECISIONS.md`。

---

## 3. 硬性禁止

以下每一条都会让项目走偏。不要"顺手"做：

| 禁止 | 为什么 |
|------|--------|
| 实现 MTProto / fork Telegram 客户端（tweb、telegram-react） | 那是另一个项目，工作量以人年计。见 `02` 需求文档 §10 |
| 用 Socket.IO 代替裸 `ws` | 它自带上层协议语义，会和自研帧格式打架 |
| 用时间戳做消息序号 | 同毫秒多条消息会乱序，断线补齐直接失效 |
| 每个流式 token 写一次数据库 | 磁盘与事件循环都会被打爆 |
| 把 token 放进 URL 查询串 | 会进反向代理访问日志 |
| 引入 Redis / Kafka / GraphQL / 微服务 | v1 单进程足够。加一层就多一个能挂的地方 |
| 引入 Prisma | 选型已定 Drizzle。换 ORM 会让迁移脚本重写 |
| 用 Next.js | 只需要 SPA，不需要 SSR；多出来的部署面没有收益 |
| 做端到端加密、语音视频、移动端 App、多语言 | 都在 `01` 的"明确不做"里 |
| 跳过 `@agentlink/protocol` 包手写帧 | 类型分叉是这个项目最贵的债 |
| 一次性写完所有里程碑 | 见 §5 |

## 4. 完成定义（DoD）

一个里程碑算完成，必须同时满足：

- [ ] `pnpm -r build` 通过
- [ ] `pnpm -r typecheck` 通过
- [ ] 该里程碑的验收脚本通过，且**把输出贴进提交说明**
- [ ] 新增/改动的帧、op、evt 已进 `packages/protocol`，服务端与客户端都从它引用
- [ ] 主路径上没有 `TODO` / `FIXME`
- [ ] `docs/PROGRESS.md` 追加一行

**没跑通验收脚本的里程碑不算完成**，不管代码看起来多完整。

---

## 5. 里程碑纪律

- **严格串行**：M2 的验收没过，不许开 M3。
- 每个里程碑单独提交，提交信息前缀 `M2:`。
- 一个里程碑内可以多次提交，但不要跨里程碑混提交。
- 如果你发现某个里程碑需要 3 天以上，先把范围砍到能跑验收为止，缺的记进 `docs/DECISIONS.md`。

这条纪律的理由：协议设计的错误在 M3 才暴露（seq 模型），在 M4 才暴露（rev 规则）。早点跑验收，返工成本低一个数量级。

---

## 6. 遇到规格空白的决策流程

1. **先查**：`02`、`03` 里是否已定义。多数"空白"其实有答案。
2. **能不加东西就不加**：优先用现有 op/evt 组合实现。
3. **要加新 op 或新 evt** → 停。这属于协议变更，**必须先问**，不能自己加。
4. **实现细节的空白**（比如某个字段用数组还是对象）→ 自己定，记进 `docs/DECISIONS.md`：

```markdown
## 2026-11-20 · typing 事件的去抖
**问题**：连续输入会产生过多 typing 帧。
**选择**：客户端侧 2 秒节流。
**理由**：服务端节流会在多客户端场景下互相覆盖。
```

5. **发现需求本身有矛盾** → 停下并说明，不要猜。

## 7. 改名

工作名 `AgentLink` 出现在两处：

- 包名：`@agentlink/protocol`、`@agentlink/server`、`@agentlink/web`、`@agentlink/agent-sdk`
- 协议标识：WS 子协议字符串 `agentlink.v1`

改名 = 全局替换 `agentlink` → 新名（小写），`AgentLink` → 新名（首字母大写）。除此之外不需要改任何东西。**不要**把名字写进数据库或协议帧里。

## 8. 陷阱自查表

提交前逐条过一遍。这些是这类项目最常见、也最难在事后发现的问题。

**序号**
- [ ] `events.seq` 是 `INTEGER PRIMARY KEY AUTOINCREMENT`，不是裸 `INTEGER PRIMARY KEY`
- [ ] 消息写入与 seq 分配在同一个事务里
- [ ] 没有任何地方用 `created_at` 排序代替 `seq`

**流式**
- [ ] `message.update` 的 `seq` 是 `null`
- [ ] 流式期间不逐条写库，按 500ms / 512 字符节流
- [ ] `rev` 从 0 开始，服务端每帧 +1
- [ ] 客户端检测到 `rev` 跳变会调 `message.get` 重置
- [ ] 60 秒无 delta 自动 abort
- [ ] 启动时清理残留的 `streaming` 消息

**安全**
- [ ] token 只在帧体内，不在 URL
- [ ] agent token 存的是 hash，不是明文
- [ ] 附件下载校验群成员身份
- [ ] 人类口令用 argon2id（不是 sha256）

**协议正确性**
- [ ] 未知 `evt.type` 被忽略，不报错
- [ ] 未知 `op` 回 `UNSUPPORTED_OP`，**不断开连接**
- [ ] 单帧超 1 MiB 回 `PAYLOAD_TOO_LARGE`，**不断开连接**
- [ ] `client_msg_id` 重复时不报错，返回已有消息
- [ ] 订阅过滤在服务端执行，不是推给客户端再丢

**补齐**
- [ ] 客户端持久化 `last_seq`，重连用 `resume` 而不是重拉全量
- [ ] `gap:true` 时客户端走全量重同步
- [ ] `events` 有 30 天清理任务

**管理**
- [ ] 权限判定对 agent 与人类走同一套代码
- [ ] 审计日志只写**成功**的动作
- [ ] 限流超限返回 `RATE_LIMITED`，不静默丢弃

## 9. 当你卡住时

按顺序尝试：

1. 用 `scripts/acceptance/_client.mjs` 手搓一个最小复现，比读代码快。
2. 检查是不是撞了 §8 的某一条。
3. 检查是不是同一条帧被两个地方都解析了（`protocol` 包应该是唯一解析点）。
4. 如果怀疑协议本身有问题，**先不要改协议**，在 `docs/DECISIONS.md` 里写下问题，实现一个绕过方案让验收先过，然后报告。
