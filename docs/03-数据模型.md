# 03 · 数据模型（SQLite）

配套 `02-协议规范.md`。这里的 DDL 是基线，实现可以加字段，**不得删改语义**。

约定：

- 所有时间戳为 **unix 毫秒整数**（`INTEGER`）。
- 所有 ID 为**带前缀的 ULID 字符串**：`u_`（用户/agent）、`c_`（会话）、`m_`（消息）、`a_`（附件）、`e_`（事件）。
- `tenant_id` 默认 `'default'`，v1 恒为此值，但每张业务表都要有（需求 D4 的预留）。
- 布尔用 `INTEGER` 0/1。

---

## 1. 建表

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

-- 人类与 agent 共用一张表（需求 D3：同权）
CREATE TABLE users (
  id            TEXT PRIMARY KEY,
  tenant_id     TEXT NOT NULL DEFAULT 'default',
  kind          TEXT NOT NULL CHECK (kind IN ('human','agent')),
  username      TEXT NOT NULL,
  display_name  TEXT NOT NULL,
  avatar_url    TEXT,
  password_hash TEXT,          -- 仅 human，argon2id
  token_hash    TEXT,          -- 仅 agent，见 §5
  model         TEXT,          -- 仅 agent，展示用
  owner_user_id TEXT REFERENCES users(id),  -- agent 的属主
  disabled      INTEGER NOT NULL DEFAULT 0,
  created_at    INTEGER NOT NULL
);
CREATE UNIQUE INDEX ux_users_username ON users(tenant_id, username);

CREATE TABLE conversations (
  id           TEXT PRIMARY KEY,
  tenant_id    TEXT NOT NULL DEFAULT 'default',
  kind         TEXT NOT NULL CHECK (kind IN ('group','dm')),
  title        TEXT NOT NULL DEFAULT '',
  announcement TEXT NOT NULL DEFAULT '',
  created_by   TEXT NOT NULL REFERENCES users(id),
  created_at   INTEGER NOT NULL
);

CREATE TABLE memberships (
  conv_id      TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  user_id      TEXT NOT NULL REFERENCES users(id),
  role         TEXT NOT NULL CHECK (role IN ('owner','admin','member')),
  is_agent     INTEGER NOT NULL DEFAULT 0,   -- 仅标记，v1 不参与鉴权
  muted_until  INTEGER NOT NULL DEFAULT 0,
  joined_at    INTEGER NOT NULL,
  PRIMARY KEY (conv_id, user_id)
);
CREATE INDEX ix_memberships_user ON memberships(user_id);

CREATE TABLE messages (
  id             TEXT PRIMARY KEY,
  tenant_id      TEXT NOT NULL DEFAULT 'default',
  conv_id        TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  sender_id      TEXT NOT NULL REFERENCES users(id),
  seq            INTEGER,          -- 对应 events.seq；streaming 期间为 NULL
  client_msg_id  TEXT,             -- 幂等键
  content_json   TEXT NOT NULL,    -- 块数组 JSON
  text_plain     TEXT NOT NULL DEFAULT '',  -- 供 FTS 与 context 使用
  reply_to       TEXT REFERENCES messages(id),
  state          TEXT NOT NULL CHECK (state IN ('streaming','final','revoked')),
  interrupted    INTEGER NOT NULL DEFAULT 0,
  created_at     INTEGER NOT NULL,
  finalized_at   INTEGER,
  revoked_at     INTEGER,
  revoked_by     TEXT REFERENCES users(id)
);
CREATE INDEX ix_messages_conv_seq ON messages(conv_id, seq DESC);
CREATE UNIQUE INDEX ux_messages_idem ON messages(sender_id, client_msg_id)
  WHERE client_msg_id IS NOT NULL;
CREATE INDEX ix_messages_streaming ON messages(state) WHERE state = 'streaming';

-- 事件日志：断线补齐的唯一来源
CREATE TABLE events (
  seq        INTEGER PRIMARY KEY AUTOINCREMENT,  -- 见 §4，AUTOINCREMENT 不可省
  tenant_id  TEXT NOT NULL DEFAULT 'default',
  conv_id    TEXT,               -- 非会话事件为 NULL
  type       TEXT NOT NULL,
  payload    TEXT NOT NULL,      -- 完整 evt.data 的 JSON
  created_at INTEGER NOT NULL
);
CREATE INDEX ix_events_conv_seq ON events(conv_id, seq);

CREATE TABLE attachments (
  id          TEXT PRIMARY KEY,
  tenant_id   TEXT NOT NULL DEFAULT 'default',
  uploader_id TEXT NOT NULL REFERENCES users(id),
  filename    TEXT NOT NULL,
  mime        TEXT NOT NULL,
  size        INTEGER NOT NULL,
  sha256      TEXT NOT NULL,
  path        TEXT NOT NULL,        -- 相对存储根的 content-addressed 路径
  created_at  INTEGER NOT NULL
);
CREATE INDEX ix_attachments_sha ON attachments(sha256);

CREATE TABLE audit_logs (
  id          TEXT PRIMARY KEY,
  tenant_id   TEXT NOT NULL DEFAULT 'default',
  actor_id    TEXT NOT NULL REFERENCES users(id),
  action      TEXT NOT NULL,        -- member.kick / member.mute / member.role.set / group.update / agent.create ...
  target_type TEXT NOT NULL,        -- user / group / agent
  target_id   TEXT NOT NULL,
  detail      TEXT NOT NULL DEFAULT '{}',
  created_at  INTEGER NOT NULL
);
CREATE INDEX ix_audit_created ON audit_logs(created_at DESC);
```

## 2. 全文检索

```sql
CREATE VIRTUAL TABLE messages_fts USING fts5(
  text_plain,
  content='messages',
  content_rowid='rowid',
  tokenize='unicode61'
);

-- 只索引终态消息；agent 回复也进索引
CREATE TRIGGER trg_messages_ai AFTER INSERT ON messages
WHEN new.state = 'final' AND new.revoked_at IS NULL
BEGIN
  INSERT INTO messages_fts(rowid, text_plain) VALUES (new.rowid, new.text_plain);
END;

CREATE TRIGGER trg_messages_ad AFTER DELETE ON messages BEGIN
  INSERT INTO messages_fts(messages_fts, rowid, text_plain)
  VALUES('delete', old.rowid, old.text_plain);
END;

CREATE TRIGGER trg_messages_au AFTER UPDATE ON messages
WHEN old.state = 'final' OR new.state = 'final'
BEGIN
  INSERT INTO messages_fts(messages_fts, rowid, text_plain)
  VALUES('delete', old.rowid, old.text_plain);
  INSERT INTO messages_fts(rowid, text_plain)
  SELECT new.rowid, new.text_plain WHERE new.state = 'final' AND new.revoked_at IS NULL;
END;
```

命中片段用 FTS5 内置函数，不要自己在应用层截字符串：

```sql
SELECT m.id, m.conv_id, m.seq, m.sender_id, m.created_at,
       snippet(messages_fts, 0, '<mark>', '</mark>', '…', 12) AS excerpt
FROM messages_fts
JOIN messages m ON m.rowid = messages_fts.rowid
WHERE messages_fts MATCH ?
  AND m.tenant_id = ?
ORDER BY m.seq DESC
LIMIT 50;
```

注意 `tokenize='unicode61'` 对中文是**按字切分**，能用但不理想。v1 接受这个质量；要更好的中文分词需自建 tokenizer，**不在第一版范围**。

| 索引 | 支撑的查询 |
|------|-----------|
| `ux_messages_idem` | `client_msg_id` 幂等（协议 §5.3） |
| `ix_messages_conv_seq` | `history.fetch` 按 seq 倒序分页 |
| `ix_events_conv_seq` | `resume` 按 seq 升序补发 |
| `ix_memberships_user` | `conv.list`（我加入了哪些群） |
| `ix_messages_streaming` | 启动时清理僵尸流式消息（§6.4） |

## 4. seq 分配（最容易写错的一处）

```sql
INSERT INTO events(tenant_id, conv_id, type, payload, created_at)
VALUES (?, ?, ?, ?, ?)
RETURNING seq;
```

三条硬性要求：

1. **必须 `INTEGER PRIMARY KEY AUTOINCREMENT`**，不能用裸 `INTEGER PRIMARY KEY`。后者在删除行后会**复用 rowid**，客户端会以为收到旧消息。
2. **必须在写 `messages` 的同一个事务里分配**。先写消息后分配 seq 会产生"有消息无事件"的窗口。
3. **只有一个写入者**。SQLite 单写多读，`better-sqlite3` 的同步调用天然串行，不要引入并行写。

流式消息在 `commit` 时才分配 seq（`streaming` 期间 `messages.seq` 为 `NULL`），因为 `message.update` 本就不带 seq。

## 5. Agent token

- 生成：`ag_` + 32 字节 CSPRNG base62。**只在创建时返回一次**，之后无法再取出。
- 存储：`token_hash = sha256(secret + server_pepper)`。agent token 是长随机串，用 sha256 足够；人类口令必须 argon2id。
- 校验：解析前缀取出 `user_id`（token 格式 `ag_<user_id>_<secret>`），查库比对 hash，常数时间比较。
- 轮换：`POST /api/admin/agents/:id/rotate-token` → 旧 token 立即失效，同时断开该 agent 的所有 WS 连接。

## 6. 三条必须落实的运行时规则

### 6.1 流式节流写入

`stream.delta` **不写库**。按 500ms 或 512 字符（先到者）触发一次：

```sql
UPDATE messages
SET content_json = ?, text_plain = ?
WHERE id = ? AND state = 'streaming';
```

流式文本在内存里累积，`content_json` 只存一个 `text` 块。

### 6.2 幂等

重复的 `(sender_id, client_msg_id)` 命中唯一索引 → 捕获 `SQLITE_CONSTRAINT_UNIQUE` → 查出已有消息 → 正常返回 `message_id, seq`。**不要向客户端报错。**

### 6.3 离线补齐的保留策略

`events` 会无限增长。策略：

- 保留 **30 天**，定时任务（每 10 分钟）删 `created_at < now - 30d` 的行。
- 客户端 `last_seq` 小于最早保留的 seq 时，`resume` 返回 `gap: true`。
- `gap:true` 时客户端必须**全量重同步**（重新拉 `conv.list` + 每会话 `history.fetch`），而不是期望补发。

### 6.4 僵尸流式消息

启动时执行一次：

```sql
UPDATE messages
SET state = 'final', finalized_at = <now>
WHERE state = 'streaming' AND created_at < <now - 120s>;
```

内容为空的直接删除。

`120s` 是清理阈值，**不是**超时阈值：协议 §8.5 规定 60 秒无 delta 就由定时器 abort，这里的 120 秒是给进程崩溃留的余量。两者不要合并成一个数——前者是业务超时，后者是崩溃残留的兜底。

## 7. 迁移

用 Drizzle 的 migration 目录，**必须**具备：

- `pnpm --filter @agentlink/server db:generate` 生成 SQL。
- 启动时自动执行未应用的迁移（单进程部署，不需要迁移锁）。
- 第一个迁移就是上面 §1 的全部 DDL。
- 迁移文件**只增不改**。

## 8. 与 Postgres 的边界（预留，不实现）

需要迁移到 Postgres 时，以下三处需要改，其余不用：

1. `AUTOINCREMENT` → `BIGSERIAL`（或 `GENERATED ALWAYS AS IDENTITY`）。
2. FTS5 → `tsvector` + `GIN` 索引，`snippet()` → `ts_headline()`。
3. 部分索引语法（`WHERE client_msg_id IS NOT NULL`）Postgres 语法一致，可直接用。

`better-sqlite3` 的同步 API → 需改成异步驱动，这是唯一有蔓延性的改动。所以**所有数据库访问必须收敛在 `packages/server/src/db/` 目录内**，不得散落到路由代码里。
