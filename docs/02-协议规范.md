# 02 · 协议规范（AgentLink v1）

工作名 `AgentLink`，包名 `@agentlink/*`。改名只需全局替换两处字符串，见 `05-施工守则.md` §7。

本文件是**规范**，不是建议。实现必须按此执行；与本文冲突的写法一律视为 bug。

---

## 1. 传输

| 通道 | 用途 | 形式 |
|------|------|------|
| 实时 | 收发消息、事件推送、流式 | WebSocket `GET /ws` |
| 控制面 | 登录、历史分页、搜索、文件上传、管理 | HTTP REST，前缀 `/api` |
| 健康检查 | 存活探测 | `GET /healthz` → `200 {"ok":true}` |

- WS 帧一律为 **JSON 文本帧**，UTF-8 编码。
- 单帧上限 1 MiB。超限回 `PAYLOAD_TOO_LARGE`，**不断开连接**。
- 第一版不用二进制帧。可调试性优先于带宽，要能用手打的客户端验证。

---

## 2. 握手与认证

浏览器的 WebSocket API **无法设置自定义请求头**，所以认证不靠 header，靠首帧。

```
连接建立
  → 服务端等待 auth 帧，超时 5 秒
  → 成功：回 ready 响应
  → 失败：回 error 响应，服务端 close(1008)
```

### 2.1 认证请求

```json
{"v":1,"kind":"req","id":"r1","op":"auth","data":{"token":"<jwt 或 agent token>"}}
```

### 2.2 成功

```json
{"v":1,"kind":"res","id":"r1","ok":true,
 "data":{
   "protocol":1,
   "self":{"id":"u_01J...","kind":"agent","display_name":"助手","tenant_id":"default"},
   "server_time":1737000000000
 }}
```

### 2.3 失败

```json
{"v":1,"kind":"res","id":"r1","ok":false,
 "error":{"code":"AUTH_INVALID","message":"token 无效"}}
```

### 2.4 硬性要求

- **token 只出现在帧体内，不得出现在 URL 查询串里**（会进反向代理访问日志）。
- 未认证连接**不得**收到任何 `evt`。
- 一个连接对应一个身份。切换身份必须重连。

## 3. 帧信封

只有三种 `kind`。

### 3.1 `req`（客户端 → 服务端）

| 字段 | 类型 | 必备 | 说明 |
|------|------|------|------|
| `v` | int | 是 | 协议版本，恒为 `1` |
| `kind` | `"req"` | 是 | |
| `id` | string | 是 | 客户端生成，连接内唯一，用于匹配响应 |
| `op` | string | 是 | 操作名，见 §5 |
| `data` | object | 否 | 操作参数，缺省为 `{}` |

```json
{"v":1,"kind":"req","id":"r7","op":"message.send",
 "data":{"conv_id":"c_01J...","client_msg_id":"3f2a...-uuid","content":[{"type":"text","text":"你好"}]}}
```

### 3.2 `res`（服务端 → 客户端）

成功：

```json
{"v":1,"kind":"res","id":"r7","ok":true,
 "data":{"message_id":"m_01J...","seq":1036,"client_msg_id":"3f2a...-uuid","created_at":1737000000123}}
```

失败：

```json
{"v":1,"kind":"res","id":"r7","ok":false,
 "error":{"code":"PERM_DENIED","message":"你不是管理员","details":{"action":"member.kick"}}}
```

`error.details` 可选，结构随 `code` 而定，客户端不得依赖未在 §9 定义的结构。

### 3.3 `evt`（服务端 → 客户端，推送）

| 字段 | 类型 | 必备 | 说明 |
|------|------|------|------|
| `v` | int | 是 | `1` |
| `kind` | `"evt"` | 是 | |
| `type` | string | 是 | 事件名，见 §6 |
| `seq` | int \| null | 是 | 见 §4。瞬时事件为 `null` |
| `ts` | int | 是 | 服务端毫秒时间戳，仅用于展示 |
| `data` | object | 是 | 事件负载 |

```json
{"v":1,"kind":"evt","type":"message.new","seq":1036,"ts":1737000000123,
 "data":{"conv_id":"c_01J...","message":{...}}}
```

**规则**：`evt` 永不带 `id`。`evt` 不需要客户端回应。

## 4. 序号与断线补齐

### 4.1 模型

**全服务器单一单调递增 `seq`**，由 `events` 表分配（见 `03-数据模型.md` §4）。

- 需要补发的事件带 `seq`（整数，全局唯一，严格递增）。
- 瞬时事件 `seq = null`：**不持久化、不补发**。目前只有 `typing` 和 `poke` 的动画提示属于此类。
- 客户端持久化它见过的**最大** `seq` 为 `last_seq`。

### 4.2 补齐流程

```json
// C→S
{"v":1,"kind":"req","id":"r2","op":"resume","data":{"last_seq":1023}}
// S→C
{"v":1,"kind":"res","id":"r2","ok":true,"data":{"replayed":12,"up_to":1035,"gap":false}}
```

服务端按 `seq` 升序补发 `seq > 1023` 且该连接**有权接收**的事件，补完再回上面的 `res`。

**`gap` 语义**：`events` 表只保留 30 天（见 `03-数据模型.md` §6.3）。若 `last_seq` 早于最早保留的事件，补发不可能完整，服务端回 `gap:true`（此时 `replayed` 可能为 0）。客户端收到 `gap:true` 必须**全量重同步**（`conv.list` + 逐会话 `history.fetch`），不得假定补齐成功。

### 4.3 禁止事项（这是最常见的实现错误）

- **seq 有空洞是正常的。** 全局计数器下，别人会话的事件不会推给你。客户端**不得**按连续序列校验，只记录最大值。
- **禁止用时间戳代替 seq。** 同一毫秒多条消息会乱序。
- **禁止每会话独立计数。** 断线补齐会退化成 N 次查询。
- **禁止在内存里发号。** 进程重启后序号会回退，客户端会永久丢消息。

这一节是验收标准第 3 条（杀掉 agent 进程 1 分钟再启动）的唯一实现方式。

## 5. 操作清单（`req.op`）

所有 `op` 的参数名与返回字段按此表。`conv_id` 类字段一律为字符串 ID。

### 5.1 认证与连接

| op | 参数 | 返回 | 说明 |
|----|------|------|------|
| `auth` | `token` | `protocol,self,server_time` | 必须为首帧 |
| `resume` | `last_seq` | `replayed,up_to,gap` | 补齐离线事件，见 §4 |
| `subscribe.set` | `filters` | `applied` | 声明关心什么，见 §5.6 |
| `ping` | — | `server_time` | 保活，客户端每 30s 发一次 |

### 5.2 会话

| op | 参数 | 返回 |
|----|------|------|
| `conv.list` | `limit?`,`cursor?` | `items[],next_cursor?` |
| `conv.create` | `kind`(`group`\|`dm`),`title?`,`member_ids?` | `conv` |
| `conv.get` | `conv_id` | `conv,members[]` |
| `group.update` | `conv_id`,`title?`,`announcement?` | `conv` |

### 5.3 消息

| op | 参数 | 返回 |
|----|------|------|
| `message.send` | `conv_id`,`client_msg_id`,`content[]`,`reply_to?` | `message_id,seq,client_msg_id,created_at` |
| `message.get` | `conv_id`,`message_id` | `message` |
| `message.revoke` | `conv_id`,`message_id` | `ok` |
| `history.fetch` | `conv_id`,`before_seq?`,`limit?`(≤100,默认 50) | `messages[]`(seq 降序),`has_more` |
| `context.fetch` | 见 §7 | `messages[],truncated,dropped_count` |

`content` 是**块数组**，不是字符串：

```json
[{"type":"text","text":"看这个"},
 {"type":"image","attachment_id":"a_01J..."}]
```

块类型第一版只允许 `text`、`image`、`file`。`text` 最大 8000 字符；单条消息最多 20 块。

**`client_msg_id` 是幂等键**：客户端生成 UUID v4。服务端遇到重复的 `(sender_id, client_msg_id)` **不报错**，直接返回已存在消息的 `message_id` 与 `seq`。这是重连重发的安全网。

### 5.4 流式（agent 回复）

| op | 参数 | 返回 |
|----|------|------|
| `stream.begin` | `conv_id`,`client_msg_id`,`reply_to?` | `message_id,conv_id,rev` |
| `stream.delta` | `conv_id`,`message_id`,`delta` | `ok`（通常不回，见 §8） |
| `stream.commit` | `conv_id`,`message_id` | `message`（最终态） |
| `stream.abort` | `conv_id`,`message_id`,`reason?` | `message` |
| `stream.interrupt` | `conv_id`,`message_id` | `ok` | 人类打断 agent 生成 |

### 5.5 成员与群管理

| op | 参数 | 返回 | 所需角色 |
|----|------|------|----------|
| `member.invite` | `conv_id`,`user_ids[]` | `members[]` | admin |
| `member.kick` | `conv_id`,`user_id` | `ok` | admin |
| `member.mute` | `conv_id`,`user_id`,`until_ms`(0=解除) | `ok` | admin |
| `member.role.set` | `conv_id`,`user_id`,`role` | `ok` | owner |
| `poke.send` | `conv_id`,`user_id` | `ok` | member |

### 5.6 订阅

`subscribe.set` 决定该连接收到哪些 `evt`。默认（不调用）为"全部可见会话 + 全部事件类型"。

```json
{"v":1,"kind":"req","id":"r9","op":"subscribe.set","data":{"filters":{
  "conv_ids":["c_01J...","c_02J..."],
  "event_types":["message.new","message.revoke","member.join"],
  "only_mentions":true
}}}
```

- 三个字段都可省略：`conv_ids` 省略 = 全部可见；`event_types` 省略 = 全部类型。
- `only_mentions:true` 时，`message.new` 只在该消息 @ 了本用户时推送。
- **过滤在服务端做**，不是客户端收到再丢。这是本项目相对 QQ 协议端的核心差异之一。

### 5.7 检索

| op | 参数 | 返回 |
|----|------|------|
| `search.messages` | `q`,`conv_id?`,`from_user_id?`,`before?`,`after?`,`limit?` | `hits[]` |

`hits` 元素：`{message_id,conv_id,seq,sender_id,excerpt,created_at}`。`excerpt` 是命中片段，前后各约 40 字符，命中词用 `<mark>` 包裹。

## 6. 事件清单（`evt.type`）

| type | seq | 负载 | 说明 |
|------|-----|------|------|
| `message.new` | 有 | `conv_id,message` | 新消息（含流式消息的空初始态） |
| `message.update` | **null** | `conv_id,message_id,rev,delta` | 流式增量，见 §8 |
| `message.final` | 有 | `conv_id,message` | 流式结束，附带最终完整消息 |
| `message.revoke` | 有 | `conv_id,message_id,by` | 撤回 |
| `member.join` | 有 | `conv_id,member` | |
| `member.leave` | 有 | `conv_id,user_id,reason` | |
| `member.update` | 有 | `conv_id,member` | 昵称/角色/禁言变化 |
| `group.update` | 有 | `conv_id,conv` | 群名、公告 |
| `typing` | null | `conv_id,user_id` | 瞬时，3 秒有效 |
| `poke` | null | `conv_id,from_user_id,to_user_id` | |

**未知 `type` 客户端必须忽略**，不得报错、不得断开。这是前向兼容的硬要求。

### 消息对象

```json
{
  "id":"m_01J...",
  "conv_id":"c_01J...",
  "seq":1036,
  "sender":{"id":"u_01J...","kind":"agent","display_name":"助手"},
  "content":[{"type":"text","text":"你好"}],
  "reply_to":null,
  "state":"final",
  "interrupted":false,
  "created_at":1737000000123,
  "revoked_at":null
}
```

`state` ∈ `streaming` | `final` | `revoked`。`interrupted` 仅在流式回复被人类打断（§8.4）时为 `true`。

## 7. `context.fetch`：本项目最关键的一个接口

**设计目标**：agent 拿到返回结果就能直接拼 prompt，不需要自己维护消息库。

### 请求

```json
{"v":1,"kind":"req","id":"r11","op":"context.fetch","data":{
  "conv_id":"c_01J...",
  "anchor_seq":1036,
  "before":20,
  "after":0,
  "include_quoted":true,
  "max_chars":8000
}}
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `anchor_seq` | 可省 | 省略 = 最新消息 |
| `before` | 20 | 锚点之前取多少条，上限 100 |
| `after` | 0 | 锚点之后取多少条，上限 100 |
| `include_quoted` | true | 是否内联被引用消息的文本 |
| `max_chars` | 8000 | 总字数预算，超出时从最旧的消息开始丢弃 |

### 返回

```json
{"v":1,"kind":"res","id":"r11","ok":true,"data":{
  "messages":[
    {"seq":1034,"ts":1737000000000,"sender":"小明","sender_id":"u_02J...",
     "sender_kind":"human","text":"周报什么时候交","quote":null},
    {"seq":1035,"ts":1737000001000,"sender":"助手","sender_id":"u_01J...",
     "sender_kind":"agent","text":"这周五","quote":"周报什么时候交"}
  ],
  "truncated":false,
  "dropped_count":0
}}
```

### 契约

- `messages` 按 `seq` **升序**（旧 → 新），可直接顺序拼进 prompt。
- `sender` 是**展示名**，不是 ID。`sender_id` 单独给。
- `quote` 是被引用消息的纯文本（最长 200 字符）；无引用为 `null`。
- 附件不返回二进制，只在 `text` 里以 `[图片]`、`[文件: report.pdf]` 占位。
- `truncated:true` 表示因 `max_chars` 预算不足而丢弃了旧消息，`dropped_count` 给数量。
- 已撤回消息**不返回**，也不占 `dropped_count`。
- 请求方不在该群内 → `PERM_DENIED`。

## 8. 流式协议时序

流式是本项目的另一核心差异点。设计约束：**不能每收到一个 token 就写一次数据库**（见 `03-数据模型.md` §6）。

### 8.1 时序

```
agent                          server                     web 客户端
  │── stream.begin ────────────▶│
  │                             │── evt message.new (state=streaming, content=[]) ──▶│
  │◀── res {message_id, rev:0} ─│                            │
  │── stream.delta "你" ───────▶│
  │                             │── evt message.update {rev:1, delta:"你"} ─────────▶│
  │── stream.delta "好" ───────▶│
  │                             │── evt message.update {rev:2, delta:"好"} ─────────▶│
  │── stream.commit ───────────▶│  （落库最终文本）
  │◀── res {message} ───────────│── evt message.final {message} ────────────────────▶│
```

### 8.2 `rev` 规则

- `rev` 从 `0` 开始，每次 `stream.delta` 后服务端 `rev += 1`。
- 客户端期望收到 `rev = 本地rev + 1`。
- **若收到的 `rev` 跳变**（说明中间丢了帧），客户端必须调 `message.get` 拉当前完整文本并重置本地状态，**不得**自行拼接出不一致的文本。

这一条让 `message.update` 可以完全走内存、不落库，同时保证丢帧可恢复。

### 8.3 落库节流

- `message.update` 事件**不写 `events` 表**（`seq = null`）。
- 流式期间的当前文本按**每 500ms 或每 512 字符**（取先到者）写入 `messages.content_json`，`state='streaming'`。
- `stream.commit` 时写最终态，`state='final'`，并写一条 `message.final` 事件（带 seq）。

这样最坏情况服务端崩溃只丢 500ms 的生成内容。

### 8.4 打断

`stream.interrupt` 由人类成员发出。服务端：
1. 向该消息的生成方（agent 连接）推 `evt message.update` 不足以保证送达，改为显式关闭其流式上下文；
2. agent 的 SDK 收到 `STREAM_CLOSED` 错误后必须停止发 delta；
3. 服务端以当前已累积文本 `commit`，消息标记 `state='final'` 且附加 `interrupted:true`。

### 8.5 超时

`stream.begin` 后 60 秒内无任何 `stream.delta`，服务端自动 `abort` 并推 `message.final`（内容为空则该消息被删除并推 `message.revoke`）。

## 9. 错误码

`code` 是**稳定的字符串**，可被客户端程序分支。`message` 是给人看的中文描述，可随意改。

| code | 含义 | 客户端应做的事 |
|------|------|----------------|
| `AUTH_REQUIRED` | 未认证就发非 auth 帧 | 发 auth 或重连 |
| `AUTH_INVALID` | token 无效 | 刷新 token 后重试一次 |
| `AUTH_EXPIRED` | token 过期 | 走刷新流程 |
| `UNSUPPORTED_VERSION` | `v` 不是 1 | 提示升级客户端 |
| `UNSUPPORTED_OP` | 未知 `op` | 视为服务端版本较旧，降级 |
| `PERM_DENIED` | 无权限 | 提示，不重试 |
| `NOT_FOUND` | 对象不存在 | 刷新列表 |
| `VALIDATION_FAILED` | 参数不合 schema | `details.issues` 为 Zod 错误数组 |
| `RATE_LIMITED` | 超限 | 等 `details.retry_after_ms` 后重试 |
| `PAYLOAD_TOO_LARGE` | 单帧超 1 MiB | 拆分或改走 HTTP 上传 |
| `STREAM_CLOSED` | 流已被 commit/abort/打断 | 停止发 delta |
| `CONFLICT` | 状态冲突（如已撤回再撤回） | 拉最新状态 |

## 10. 权限矩阵

角色取 `memberships.role`。agent 与人类**用同一套判定**（见需求 D3）。

| 动作 | owner | admin | member |
|------|:-----:|:-----:|:------:|
| 发消息（未被禁言） | ✓ | ✓ | ✓ |
| 撤回自己的消息 | ✓ | ✓ | ✓ |
| 撤回他人消息 | ✓ | ✓ | ✗ |
| 邀请成员 | ✓ | ✓ | ✗ |
| 踢人 / 禁言 | ✓ | ✓ | ✗ |
| 改群名 / 公告 | ✓ | ✓ | ✗ |
| 设/撤管理员 | ✓ | ✗ | ✗ |
| 流式生成（agent） | ✓ | ✓ | ✓ |

补充规则：

- 禁言中（`muted_until > now`）的成员发消息 → `PERM_DENIED`，`details.reason="muted"`。
- 任何管理动作**必须**写 `audit_logs`（验收第 2 条）。
- `is_agent` 标记只用于将来限权，**v1 不参与判定**。

---

## 11. 限流

令牌桶，按身份（`user_id`）计，默认：

| 动作 | 配额 |
|------|------|
| 发消息 | 30 条 / 60 秒 |
| 流式 delta | 200 帧 / 60 秒 |
| 搜索 | 20 次 / 60 秒 |
| 新建流式消息 | 5 条 / 60 秒 |

超限回 `RATE_LIMITED`，`details.retry_after_ms` 为整数。**不得**静默丢弃。

v1 的配额是服务端常量，不落库、不做配置界面。将来要支持按用户覆盖时，再给 `users` 加字段（迁移只增不改）。

---

## 12. 版本与兼容

- 每帧必须带 `v`。服务端只接受 `v=1`，否则 `UNSUPPORTED_VERSION`。
- **未知字段一律忽略**，不报错。
- 未知 `op` 回 `UNSUPPORTED_OP`，**不断开连接**。
- 未知 `evt.type` 客户端忽略。
- 破坏性变更 → `v=2`，服务端在一段时期内同时接受 1 和 2。

## 13. 完整交互示例

两个人类 + 一个 agent，一条流式回复。

```
① agent 连接
C: {"v":1,"kind":"req","id":"1","op":"auth","data":{"token":"ag_xxx"}}
S: {"v":1,"kind":"res","id":"1","ok":true,"data":{"protocol":1,"self":{"id":"u_a","kind":"agent",...},"server_time":...}}

② agent 只订阅被 @ 的消息
C: {"v":1,"kind":"req","id":"2","op":"subscribe.set","data":{"filters":{"conv_ids":["c1"],"only_mentions":true}}}
S: {"v":1,"kind":"res","id":"2","ok":true,"data":{"applied":true}}

③ 人类 @ 它
S: {"v":1,"kind":"evt","type":"message.new","seq":1036,"ts":...,"data":{"conv_id":"c1","message":{"content":[{"type":"text","text":"@助手 总结一下"}],...}}}

④ agent 取上下文（一步到位，不用自己攒历史）
```
