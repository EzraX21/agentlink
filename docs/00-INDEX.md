## 这是什么项目

一套**自研的、协议层原生为 AI Agent 设计的即时通讯系统**。不是挂在 QQ 上的协议端，也不是 Telegram 换后端。

- 服务端 + 自研协议 + React 单页客户端
- Agent 是与人类**同权**的虚拟用户
- 目标：agent 能按过滤订阅事件、一步取到可直接拼 prompt 的上下文、流式回复并可被打断

## 已定的决定

| 项 | 结论 |
|---|---|
| 形态 | 自研服务端 + 自研协议 + React 单页 |
| 客户端 | React 19 + Vite 8，视觉参照 Telegram Desktop，**不复用 Telegram 代码** |
| Agent 身份 | 虚拟用户，与人类同权（`is_agent` 只做标记，v1 不参与鉴权） |
| 接入方式 | 自定义 REST/WS，不实现 OneBot |
| 多用户 | 单租户部署，表结构带 `tenant_id` 预留 |
| 运行时 | Node 26 LTS、TypeScript strict、pnpm workspaces |
| 服务端 | Fastify 5 + `ws` + better-sqlite3 + Drizzle |
| 协议定义 | Zod，`@agentlink/protocol` 为唯一真源 |
| 存储 | SQLite（WAL）+ FTS5，预留 Postgres |
| 认证 | 人类 JWT（15m + 30d 轮换）/ Agent 长期 Bearer Token |
| 部署 | Docker + compose + Caddy |

## 验收标准（摘自需求确认书 §7）

1. 两个浏览器窗 + 一个 agent 同群：@agent 后 3 秒内出现逐字增长的流式回复 → **M4 / M9**
2. agent 禁言某成员成功，动作出现在审计日志 → **M5**
3. 杀掉 agent 进程 1 分钟再启动，凭 `last_seq` 拿回离线期间全部消息 → **M3**
4. 检索能按关键词 + 时间范围 + 发送者组合查回 → **M8**
5. WebUI 能建群、拉人、停用 agent，操作立即生效 → **M1 / M6**
6. `docker compose up` 从零起服务，刷新可用，重启不丢数据 → **M10**
